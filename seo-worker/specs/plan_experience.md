# 方案层经验（plan_review job 的输入之一，跨客户，只写规律不写客户名字里的事实）

review_principles.md 管「单个任务该不该做」，这份管「整份方案的方向对不对」。
每条一句规律加一句怎么用。来源写日期和出处，方便追溯。人推翻 fable 的判决、DEFECTS 里的方案类缺陷，都回写到这里。

## 方向

- 先定「这季度靠什么出第一单或第一批询盘」，S1 只放能直接推动它的事。SEO 上正确但离转化两步以上的，S3 以后。（2026-08 Apollo、Kuddles）
- 迁站或换平台后的客户，第一件事是把询盘追踪链路验通（表单入库、GA4 关键事件、Ads 回传），追不到就先修追踪，其他免谈。（2026-08 Apollo /contact/ 0 入库；Louvresky #95 Book a Visit 零触发）
- 已有内容拿到位置而服务页拿不到的站，方案主线是把商业意图词的承接页改成权威页形态，不是再加文章。（2026-08 Apollo）
- 只读审计（GSC/GA4/站长工具基线）不单独立任务，pull_data 覆盖；基线数字进 facts。（2026-08-29 Ben's NZ #108 drop、Apollo #100 merge）

## 任务粒度

- 博客一任务一篇。「草稿一二」这种合并任务，产线只交付一篇，另一篇丢。（2026-08-29 Ben's NZ #110）
- 单任务只动一组页面或一个主题；「同批改 X 页标题描述」这类附带项拆开，方便放行卡看清目标页。
- 分析类任务必须写清产出物（报告或清单）和它给哪个后续任务用，否则 drop。

## 范围

- 客户产品事实（价格、规格、门店、营业时间、交期、质保）只能引用客户给的，缺就占位标待提供，不立「核实」任务给机器。
- 门店信息维护是客户特例不是通用规则；多店客户默认不进方案。（2026-08 Ben's Curtains）
- 外链在有承接页之前不投；「每月外链改定向支撑承接页」放承接页上线之后的 sprint。
- 品牌铁律（禁用词、不说产地、非自产品类）在客户 CLAUDE.md，方案里任何文案类任务的 detail 必须引用它。

## 顺序

- 修承接页 → 内链指向它 → 博客引流 → 外链，四步不能倒。
- 需要客户点头的（改导航、301 旧页、删内容）放 S2 以后，S1 只放我方能独立落地的。

## paid（付费投放的方案层规律，渠道无关）

- 第一期永远是：转化口径核对（哪个 conversion action 算数、有没有注水）→ 搜索词清洗与否词包 → 结构审计。不动出价不动预算，先把地基和止血做完。
- 预算池分配是方案层唯一允许点名渠道的地方：总预算怎么在渠道间分要写理由（各渠道 CPA 与量的边际），不写就是没规划。
- 止血在输血前：否词、排除、暂停浪费组的任务排在加词、扩预算、新建 campaign 前面的 sprint。
- 学习期是排期约束：会触发重新学习的动作（改 bidding、大改预算）不和依赖稳定数据的分析任务排同一个 sprint。
- 低量账户（月转化不足 30）的方案主线是漏斗前端：落地页、QS、搜索词，不是出价策略。
- 与 organic 协同写进方案：SEO 已进前 3 的词，paid 出价下调或转竞品防守；search terms 里的高意图词反哺 SEO 选题清单。
- 素材与 copy 类任务一任务一个 ad group 批次，和博客一任务一篇同理，合并任务产线只交付一半。
- GBP 类任务只有一个合法形态：gbp-align 两件套（档案落 fact gbp.profile + 站内 LocalBusiness schema 对齐）。补照片、发帖、补产品、重写简介、问答维护这类清单项收益不可度量，一律不排任务（Alvin 2026-09-17，#42 六项清单教训：为列而列没有意义）。citation 修正等 map citation 批次统一做。
- 每个 paid 客户每月排一张方向卡，keyword-direction 与 creative-direction 逐月交替（2026-09 词卡、2026-10 素材卡，依此类推），数据窗口一律取发卡月前两个完整自然月（规则细节在 report/keyword_direction_spec.md 数据窗口节，渲染器强制）。analysis 型，产出 HTML 方向卡供 sales 与客户确认方向，反馈经任务线程回 facts，下一期词表与否词包必须引用上期确认结论。（2026-09-15 Alvin 定月度交替与窗口，取代 2026-08-31 的每 sprint 词卡）
